# Melee Ruleset

The rules package of the melee game from the design documents: each player owns one hero, an identical Nexus, and a set of buildings that raise an autonomous army from their own mana. It authors rules, not a board.

## Referenced by the board

The `ugc-SecludedCrest` repository is the composing map: its `references.json` names this map, and every save of it takes this map's files into its own folder, so the board becomes one ordinary playable map. Nothing has to be composed here, and this folder is never the map that is played.

| Into | What this map contributes |
| :--- | :--- |
| Secluded Crest v1.0.0 | `MapScript.cs`, the rules script itself, and the melee templates this map's `metadata.json` declares - units, buildings, abilities, relics and the two harvestable resource node types - plus the factions, deck and economy the script runs. |

## The board supplies the placement

This map declares no `terrain.json` and no coordinates of its own. Where the twelve resource nodes stand and where each seat begins are the board's statements, so any board authored for Melee plays by these rules unchanged:

* The four starting points are `SpawnAnchors` in the board's `terrain.json`, one per player slot. The script reads slot *n*'s point with `IGameAPI.GetSpawnAnchor(n)`, places that player's Nexus on it, and puts the hero beside it. A board with no anchor for a slot seats nobody there and says so in that player's feedback rather than inventing a position.
* The twelve resource nodes are props the board places with the template ids this map declares (`resource/melee_gold_mine` and `resource/melee_woodland`). The engine attaches the node's capacity from the template when the prop loads, so the script spawns nothing and only reads the layout, through `IGameAPI.GetResourceNodes`.
* A board that declares no anchors or places no nodes is not a Melee board. The script warns the table once at the start of a match instead of seating players somewhere arbitrary.

`metadata.json` here is merged into the board's: objects merge key by key, arrays are combined with each entry kept once by its `TemplateID`, and the board merges last, so the board's own identity, build number, shroud and camera stand while the rules, units, abilities and relics arrive from here.

Every other file comes whole from exactly one map. `MapScript.cs` is the one file the board's `references.json` states comes from this map, because the ruleset is defined here; `MapScript.csproj`, the generated templates, `Directory.Build.targets`, `NuGet.config`, `AGENTS.md`, `LICENSE.md` and `.gitignore` are kept by the board, which builds and maintains its own copies. `MapTemplates.g.cs` and `WasmEntryPoint.g.cs` are never taken from a referenced map at all.

### Prerequisites

* The board reads this map from `FolderPath` in its `references.json` while that folder exists, and otherwise from the map store by name, version and this map's pinned manifest hash.
* `manifest.json` here is the package manifest that pin names. Regenerate it with `MapManifest.CreateFromDirectory` whenever this map's content changes, then repin the board's reference to the new `ComputeManifestBlake3()`.
* `lib/` and `bin/` are this map's own workspace. The board compiles its script in its own folder from the files it takes, so the `.wasm` the game runs is never the one built here.

## What the script implements

* **One hero per player.** The lobby's faction dropdown selects Vale, Sable or Corvus, and the hero spawns beside an identical Nexus at the board's anchor for that slot. Every player starts with 200 gold and 100 wood.
* **Army level.** Every living soldier is set to the hero's level, which is the only source of army stat growth.
* **Formations and targeting.** Each soldier type holds its authored slot around the hero, rotating with the hero's facing - Front ahead, Flank to either side, Back behind - and fights by its authored rule: Standard concentrates on the target the hero last hit, Tank-Shredder takes the healthiest enemy in range, and Assassin the weakest. Slot and rule are stated in the soldier's own readings.
* **Mana and automatic production.** Each soldier-granting building carries two auto-cast abilities, one for its soldier type and one for its worker crew, and both pay from the building's single mana pool. A cast spends one production worth of mana and starts that ability's cooldown. A finished building opens with one production worth of mana and auto-casts from the first moment it is functional. The available production count is published as the building's overhead badge, including the zero it reads when the pool cannot pay, and the building's readings - the soldier it unlocks, its mana against its maximum, its regeneration, both cooldowns, its worker profile and buff and the soldiers it maintains against its capacity - are published to the inspector through `IGameAPI.SetUnitReadoutRow`, so an opponent that selects the building reads the same numbers the owner does.
* **Capacity is a map rule.** The engine's mana pool cannot state a per-type maximum, so the ruleset counts the living soldiers of each type against the summed capacity of that player's buildings that grant it, and disables the soldier ability of every granting building while the type is full. Worker capacity is counted per building. This is why relics and hero effects that change capacity live in this map's script rather than in the engine.
* **Building supply.** A player may hold eight building locations, and every constructed building costs one point of supply. The Nexus is free and does not count. A placement that would exceed the cap is refused before the wood is spent.
* **Hero death.** Losing the hero destroys the army, clears production, and schedules a revival at the Nexus, with the timer growing by three seconds per earlier death. Revival refills every building's mana.
* **Workers.** Every finished building raises workers from its own worker profile - capacity, cooldown and production cadence, separate from the soldier profile - through its own auto-cast ability and the same mana pool as its soldiers. Each worker is the same `unit/worker` template, raised at the level of the construction order of the building that raised it: the first building's workers are level 1, the next building's level 2, and so on. Workers are attackable and are replaced through their building's worker ability when killed. Each is marked as a worker, so one player's crew keeps its spacing while another player's crew walks through it.
* **Gathering is combat.** A node's health is its remaining resource: gold mines and trees are `Harvestable`, state the item each point yields, and carry armor and magic resistance from their template's per-level scaling. A worker attacks the nearest node of its assigned resource with its own attack, so damage type, penetration, critical strikes and attack speed all decide the hit; every point of post-mitigation damage becomes one piece of the node's item in the worker's inventory. Wood holds one piece per slot and gold holds five, so a full inventory is sixteen wood or eighty gold. When the worker cannot hold another piece it walks to the nearest drop-off, spends the stack into the player's stockpile, and returns. When its node is destroyed it finds the next nearest node of the same resource. The hero gathers the same way by hand.
* **Worker buffs replace income rates.** Each building applies a permanent buff to the workers it raises: armor and health for the Bulwark Hall, attack for the Warband Yard and most gold buildings, move speed for the Spear Lodge and Mender Shrine, and a slow, heavy hit for the Bolt Foundry. The buff is listed on the worker's stat panel, and the building's draft tooltip states it instead of a computed income rate. A worker's gathering rate is therefore read from its own stats, level, buffs and walk rather than advertised by its building.
* **Destroyed buildings and repair.** A drafted building reduced to zero health stays on the board as a ruin instead of leaving it: it takes no more damage, accepts no deliveries, regenerates no mana and fields no soldiers, while the mana it already held is kept, and its capacity contribution stays part of its type's total. The hero mends any allied ruin at 3% of the building's maximum health per second, so every building takes the same time to raise, and the ruin only starts working again once it is whole. The building's worker stands down while the ruin waits and walks back to its node the moment the building stands. The Nexus is the exception: it is destroyed for good and never repaired. A ruin's inspector states `Destroyed (repair to restore)` where its production line normally reads.
* **Relics.** Six relics are sold at the Nexus for 100 gold and applied player-wide while held: front-formation health, cooldown rate, damage reflection, worker attack, tenacity and soldier production cooldown.
* **Innates.** Vale's army carries flat armor and tenacity, Sable's carries Cinder Mark, and Corvus's buildings store one extra production worth of mana.
* **Bulwark.** Heroes gain armor and magic resistance from their own nearby soldiers, and the Nexus from the player's functional buildings.
* **Elimination.** Destroying a Nexus eliminates its player; the last team holding a Nexus wins.
* **Under-attack alerts** are throttled per player, name the victim, ping the minimap and play a warning.
* **Instant abilities.** Requisition advances the active construction and Emergency Levy adds one production worth of mana to every soldier-granting building.
* **The shared building deck.** Begin Construction costs 100 wood and draws up to three buildings from one deck shared by every player. The draw excludes what another player already took and what the player already stands on, and a deck with nothing left is restored before it is drawn again. The three packages are offered as commands in the hero's and Nexus's command grid; the chosen one leaves the deck, the others return, and a player who abandons the draw gets the 100 wood back. The site then builds on its own for the building's authored construction time and starts its production when the engine announces the completion.
* **Gathering and nodes.** Hero and worker gather through the same order; only the worker carries the idle-assignment tag, so a hero gathers solely when the player tells it to. A gather order plays the labor animation at the node. Trees and gold mines are selectable, show their remaining capacity and resistances, and are removed from the simulation and the board when their health reaches zero.
* **Instructions.** The map publishes its player-facing rules through `IGameAPI.AddInstructionsSection`, so the in-game instructions menu describes this ruleset's production, supply, gathering, relics and victory conditions without engine UI hard-coding them.

## Rules the engine cannot express yet

* **The silhouette and its 99% gate.** The design draws the options only after an unidentified site already stands there, and holds that site at 99% until the choice is locked. The engine cannot swap a unit's template, so the draw is answered from the command grid first and the chosen building's site appears the moment a package is cast; construction time therefore runs after the decision instead of doubling as the decision window. The reservation is published on the hero that holds the draft open, which is a unit every player can select, rather than on a site, because no site exists until the choice is locked.
